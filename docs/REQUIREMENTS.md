# チーム対抗クイズアプリ 要件定義・設計書

## 1. 概要

部のレクリエーションで使用するチーム対抗クイズアプリ。
競馬の三連単のように、1着・2着・3着を順番通りに予想する形式。
正解は事前に決まっておらず、実際にその場で実践した結果を管理者が入力して採点する。

---

## 2. 要件

### 2.1 基本要件

| 項目 | 内容 |
|------|------|
| チーム数 | 9チーム固定（A〜I） |
| 予想形式 | 三連単（1着・2着・3着を順番通りに予想） |
| 正解決定 | 管理者がその場で実践結果を入力 |
| 技術スタック | Next.js + Supabase |

### 2.2 ユーザーロール

アプリアクセス時に以下から選択：

| ロール | 説明 | 主な機能 |
|--------|------|----------|
| **チーム（A〜I）** | 各チームの代表者 | 予想の送信・変更 |
| **閲覧用** | 代表者以外のメンバー、プロジェクター表示用 | 問題・結果・順位の閲覧 |
| **管理者** | 司会・運営者 | 出題・締切・正解入力・採点 |

### 2.3 認証

- **管理者のみ**シンプルなパスワード認証（環境変数で設定、DBに保存しない）
- チーム・閲覧用は認証なし（ロール選択のみ）

---

## 3. 配点ルール

### 3.1 基本配点

| 判定 | 条件 | デフォルト点数 |
|------|------|---------------|
| 🎯 **三連単** | 1着・2着・3着すべて順番通り | 30点 |
| 📦 **三連複** | 3人全員的中（順不同） | 15点 |
| ✌️ **2的中** | 2人が3位以内に入っている | 5点 |
| ☝️ **1的中** | 1人が3位以内に入っている | 1点 |
| ❌ **ハズレ** | 誰も3位以内にいない | 0点 |

### 3.2 同着ルール

実際の結果で同着があった場合の特殊処理：

#### 1位と2位が同着の場合
- 予想の1着と2着が、実際の同着2人の組み合わせと一致すれば**両方正解扱い**
- 例：実際「田中と佐藤が同着1位」→ 予想「1着:田中、2着:佐藤」も「1着:佐藤、2着:田中」も正解

#### 2位と3位が同着の場合
- 予想の2着と3着が、実際の同着2人の組み合わせと一致すれば**両方正解扱い**
- 例：実際「佐藤と鈴木が同着2位」→ 予想「2着:佐藤、3着:鈴木」も「2着:鈴木、3着:佐藤」も正解

## 5. 進行フロー

### 5.1 クイズ進行の流れ

```
┌─────────────────────────────────────────────────────────────────┐
│                        クイズ進行フロー                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 出題        2. 予想         3. 締切        4. 実践          │
│  ┌─────┐       ┌─────┐        ┌─────┐       ┌─────┐           │
│  │管理者│──────▶│チーム│───────▶│管理者│──────▶│実際に│           │
│  │問題 │       │回答 │        │締切 │       │やる │           │
│  └─────┘       └─────┘        └─────┘       └─────┘           │
│                                                 │               │
│                                                 ▼               │
│  6. 結果発表    5. 正解決定                                      │
│  ┌─────┐       ┌─────┐                                         │
│  │スコア│◀──────│管理者│                                         │
│  │更新 │       │正解 │                                         │
│  └─────┘       └─────┘                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 問題のステータス遷移

```
pending ──▶ open ──▶ closed ──▶ revealed
  │          │         │          │
  │          │         │          │
未出題    回答受付中  回答締切   正解発表済
                      (実践中)   (採点完了)
```

| ステータス | チーム画面 | 閲覧画面 | 管理者操作 |
|-----------|-----------|---------|-----------|
| `pending` | 待機中表示 | 待機中表示 | 「出題開始」可能 |
| `open` | 予想入力可能 | 問題表示（予想は非表示） | 「回答締切」可能 |
| `closed` | 予想不可・自分の予想表示 | 全チームの予想表示 | 「正解入力」可能 |
| `revealed` | 結果表示 | 結果＋スコア表示 | 「次の問題」可能 |

### 6.2 テーブル定義

| カラム | 型 | 説明 |

#### questions（問題）

| カラム | 型 | 説明 |

| `PUT /api/answers/[id]` | PUT | 回答変更（締切前のみ） |

### 7.4 チーム

| エンドポイント | メソッド | 説明 |
|--------------|---------|------|
| `GET /api/teams` | GET | チーム一覧・スコア取得 |

## 8. リアルタイム機能

Supabase Realtimeを使用して以下をリアルタイム同期：

| 対象 | 購読するテーブル | 用途 |
|------|-----------------|------|
| 問題の状態変化 | questions | 出題開始・締切・結果発表を即座に反映 |
